## B. Drift checklist

1. **Endpoint ↔ data-model (core) ✓.** Every operation reads or writes a modelled entity. `/oauth/token` writes
   `oauth_access_tokens` and `identities`; `/api/v1/sign_out` sets `revoked_at` or rotates `users.authentication_token`;
   legacy-header requests upsert `legacy_token_uses`; the project and task operations use the existing tables.
   `oauth_applications` and `legacy_token_uses` have no operation of their own (internal), accepted.
2. **Error ↔ repo error definition (core) ✓ with a note.** No central error registry exists; the repo answers with
   message text from its services (`app/services/*`) and the `ApiExceptionHandler` / `Authorization` concerns. The
   contract uses those shapes, so there are no `module.error_name` codes. Accepted by the author.
3. **Validation ↔ constraint (core) ✓.** Project limits (5–20, 20–120), task status enum and Devise password length
   are copied from the models and initializer. Task `name` / `description` have no maximum in the model, so none is
   declared. The DB columns are nullable, the model validates presence; the contract follows the model (stricter).
4. **OpenAPI ↔ sequence (supporting) ✓ for the seeded flows.**
   - §6 flow 1 (Google sign-in): refused branch → 400 `invalid_grant` (AC-07); new user and link branches → 200 token
     pair (AC-05, AC-06).
   - §6 flow 2 (refresh): expired access token → 401, refused refresh → 400 `invalid_grant`, valid refresh → 200.
   - §6 flow 3 (dual scheme): after the cutoff or no match → 401; before it → normal answer.

## Breaking changes against `swagger/v1/swagger.json` (need the ADRs already written)

- Project and task operations: the forbidden answer for another user's item becomes not found (ADR-0007).
- Authentication: the bearer scheme and `/oauth/*` are added; the legacy headers and `/api/v1/sign_in` are kept and
  marked deprecated (ADR-0005). Removal happens in the cutoff release.
- `POST /api/v1/users`: three fields added to the result (additive, not breaking).
- `bin/swagger_smoke` and the frontend must follow the regenerated `swagger/v1/swagger.json`.

## Contract details worth confirming at implementation

- `/oauth/revoke` is a Doorkeeper route that exists once the gem is mounted; it is documented because it is reachable,
  though the web app signs out through `/api/v1/sign_out`.
- The grant name `google_id_token` and the form parameter `id_token` are chosen here; they are the contract once
  implemented.
- A bearer access token that is expired is answered with the existing 401 `Not Authorized` body, so the frontend
  refreshes once and retries (SAD §6 flow 2).
