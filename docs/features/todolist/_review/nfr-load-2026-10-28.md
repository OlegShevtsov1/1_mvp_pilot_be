## Parameters

- Seed: one user signed up through `POST /api/v1/users` (no sign-in, no failed sign-in), 50 projects × 10 tasks through
  the public API, in 45.6 s.
- Each scenario: 100 requests at 10 a second, concurrency 10; the status change sets 100 distinct tasks `in_progress`.
- Measure: `X-Runtime` (server), client round trip alongside. PASS = server p95 ≤ 300 ms and 0 % errors; nearest-rank
  percentiles over successful requests.

## Limitations

- `X-Runtime` excludes the proxy and queueing before Puma; the client time includes them and the ~325 ms network, so it
  cannot be held to 300 ms from this runner.
- Repeated dashboard lists can be served from the `Projects::Index` cache, the production path; not altered.
- One run on a shared dev box; other traffic was not controlled.
