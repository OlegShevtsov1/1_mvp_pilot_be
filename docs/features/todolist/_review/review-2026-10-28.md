## 6. Findings

### P0

- **P0-1 [stage-1] Devise's default routes are an unlimited sign-in and sign-up door** — `config/routes.rb:8`
  (`devise_for :users`), `config/application.rb:33-34` (cookie and session middleware on); AC-10, AC-04b, ADR-0009.
  `POST /users/sign_in` (`devise/sessions#create`) checks passwords without `FailedSignInLimited`, which only
  `Api::V1::SessionsController` and `Oauth::TokensController` include; `POST /users` (`devise/registrations#create`)
  creates users without the sign-up `rate_limit` of `Api::V1::UsersController`. Reproduced with a throwaway request
  spec on `5b6401a` (not committed): twelve wrong passwords in a row at `POST /users/sign_in` were all answered `401`
  (the limit is 10 a minute), and the correct password then answered `406`, so the door tells a right password from a
  wrong one; eight `POST /users` in a row created eight users (the limit is 5 an hour). `sad.md` §11 lists this risk
  ("The first auth task lists the mounted routes and keeps only those the feature needs, with a routing spec"); no
  task did it. Suggested: a regression request spec proving both doors are reachable, then remove the Devise routes
  (e.g. `devise_for :users, skip: :all`) with a routing spec — an authentication change, so it needs an ADR note
  (CLAUDE.md Hard Rules). Card: none (P0/P1 are reported here and block; fix through its own `test(` → `fix(` PR).

### P1

- **P1-1 [stage-1] AC-04b has no frontend task and no frontend test** — `tasks/tasks.json` (only T6 claims AC-04b);
  fe `src/auth/credentials.ts:105` maps a sign-up `429` to a wait message, but neither `src/routes/SignUp.test.tsx`
  nor `src/auth/credentials.test.ts` exercises it (the sign-in `429` is tested at `src/routes/SignIn.test.tsx:65`).
  AC-04b's "tells the visitor to wait" is a UI outcome on a `web-frontend` surface. Suggested: a SignUp component
  test for `429` with `Retry-After`, and AC-04b on the frontend task.
- **P1-2 [stage-1] `sad.md` §6 has flows for 3 of 10 user stories** — `docs/features/todolist/sad.md:231-311` holds
  F1 Google sign-in (AC-05/06/07), F2 token refresh (ADR-0006) and F3 dual-scheme request (AC-12/13). US-01, US-02,
  US-04, US-05, US-07, US-08, US-09 and US-10, and 20 of 25 ACs, have no flow; `sad.md:233-234` says
  `complete-sequence-diagrams` covers every AC, and it never ran. Suggested: run `complete-sequence-diagrams todolist`
  in a docs PR.
